# Secure attachment upload UI

The record-detail Overview appends a native single-file picker outside the editor form. Reuse #1095 raw-body upload, policy, authentication and source CAS. Stable revision is obtained by revision/item/revision reads and equality with the visible record; no cached global ETag substitutes for the captured precondition. Server checks remain authoritative. Client memory overhead is O(1) beyond the browser File reference; no FileReader, Base64, object URL or offline queue. Policy and explicit refresh reads use no-store.

Controls fail closed; one global pending flag survives drawer navigation. Close/open/edit disposal clears the selection and native input, without cancelling a potentially committed request. POST errors clear the selection and require explicit refresh. Late completion refreshes the list but does not reopen an unrelated drawer or overwrite a drawer editor. Success consumes only display name, media type, byte count and source revision; opaque receipt ID is ignored as access authority. Keep only the latest receipt metadata in memory and label its session scope.

Overview file/dir details become a generic attachment summary; explicit raw record/editor and generic APIs keep their operator contract. This is not a general projection/redaction feature. No download/link rendering or provider assumptions. Untrusted receipt/name text uses textContent; control/bidi names fail validation. Fixed localized error guidance avoids rendering raw server error payloads. Headers use server-selected clock header when safe, preserving remote clock preconditions.

Review viewpoints: DOM XSS/control text, exact snapshot/CSRF, permission gates, pending/navigation/resource release, failure/unknown outcomes, optional browser/Web boundaries and existing editor/capture. Rollback is revert of this PR; existing uploaded file/reference transactions remain valid and accessible through the established local tools. No destructive rollback or data migration.
