| 2026-08-08 | Fix at the CLI's stdout write site (`scripts/check_release_policy.py`) rather than reconfiguring the process-wide `sys.stdout` encoding | Claude Code | (1) `sys.stdout.reconfigure(encoding="utf-8")` at process start, (2) set `PYTHONIOENCODING=utf-8` in the recorded release-profile command | The incident's own acceptance criteria say the fix must work "without requiring the caller to know about `PYTHONIOENCODING`"; reconfiguring the global stream would also silently change encoding for any other output this script or a future caller produces, which is a larger blast radius than one write call needs | None |
| 2026-08-08 | Fall back only on `UnicodeEncodeError`, using `errors="backslashreplace"` against the stream's own declared encoding | Claude Code | `errors="replace"` (loses the exact character value, shows `?`); always re-encoding defensively even when the first write would have succeeded | `backslashreplace` keeps the escaped codepoint readable and diagnosable in the manifest text instead of losing it to a `?`; encoding defensively on every call would add work and risk on the common UTF-8 path for no benefit | None |
