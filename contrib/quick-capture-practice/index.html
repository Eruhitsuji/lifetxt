Quick Capture 練習室

Web UI と同じ流れで1行を入力し、50問で life.txt への変換を練習できます。

練習メニュー

Quick 省略記法

形式は「Quick（既定）」を選びます。1行を入力して「記録」を押すと、未完了のタスク [ ] T に変換されます。

@home
project:home（プロジェクト）
#買い物
tag:買い物（タグ）。#買い物 #家電 のように繰り返せます。
!high
priority:high（優先度）
^tomorrow
due:（期限）。日付に変換されます。

期限の書き方

固定日
^2026-12-01
相対日
^today、^tomorrow、^yesterday
曜日
^friday は次に来る金曜日、^next_friday はそこからさらに7日後、^next_week は次に来る月曜日です。同じ曜日を指定した場合、「次に来る」は7日後です。
オフセット
^+3d、^-1w、^+2m、^+1y。月・年の移動で同じ日がない場合は移動先の月末になります。

相対日はこの練習室を起動したPCの日付で計算します。記号付きの語は半角スペースで区切ります。\@home はタイトルに @home を残し、help@example.com のように語の途中にある記号もそのまま残ります。

正式な life.txt 形式

形式は「Quick（既定）」を選びます。[ で始まる入力は正式な1行として解釈されます。状態・種類・タイトルに続けて、必要な key:value を書きます。

[ ] E "定例 会議" from:2026-12-02T13:00 to:2026-12-02T14:00 loc:"会議室 A"

状態と種類

[ ] 未完了、[/] 進行中、[x] 完了、[-] キャンセル、[>] 延期・移動、[?] 保留、[N] メモ・日誌を表します。

T タスク、E 予定、D 締切、R リマインダー、H 習慣、N メモ、S 在席状況、M メッセージ、J 日誌を表します。たとえばメモは [N] N 読書メモ、進行中のタスクは [/] T 資料を作る と書きます。

よく使う詳細項目

タスク・締切
do:2026-12-01 は着手予定日、due:2026-12-05 は期限、done:2026-11-22 は完了日です。
予定
on:2026-12-02 は日付のみ。時刻が必要なら from: と to: に日時を書きます。2026-12-02T13:00+09:00 のようにUTCとの差も指定できます。
リマインダー・習慣
on:2026-12-03 at:18:30 で日付と時刻、repeat:daily at:07:30 で毎日の時刻を指定できます。
メモ・日誌
body:"第3章を読み直す" で本文、日誌では on: で日付も指定できます。
在席状況・メッセージ
在席状況は state: と from: が必要です。メッセージは sender: と recipient: が必要です。

引用符、複数値、JSON

空白を含むタイトルや値は半角の " で囲みます。引用内の半角 " は \"、バックスラッシュは \\ と書きます。詳細項目間は半角スペース1つを使います。

同じ項目を複数指定するには tag:自宅 tag:手続き と書きます。正式形式の期限は due:2026-12-01 のような日付で記述し、相対日を変換する ^tomorrow は省略記法で使います。

独自キーも使えます。たとえば options:json<< {"room":"A","seats":12} >> はオブジェクト1個です。最上位の配列は値の一覧になり、配列そのものを値1個として持たせる場合は [[...]] と書きます。意図的な独自キーでも練習結果に警告が表示されることがあります。

Quick Capture は物理的な1行を受け付けます。ファイル形式にある複数行本文や継続行は、ファイルを編集する際に使います。

life.txt フォーマット仕様

todo.txt 形式とプレビュー

形式を「todo.txt（確認必須）」に切り替えます。「プレビュー」を押し、変換された状態・期限・プロジェクトなどを確認してから「確認して記録」を押します。入力を編集したときは再プレビューします。

未完了・完了の書き方

(A) 2026-11-20 見積もりを送る +Work @office due:2026-12-01

未完了の行では、先頭に任意の優先度 (A)〜(Z)、続けて任意の作成日、その後にタイトルを書きます。

x 2026-11-22 2026-11-20 見積もりを送る +Work pri:A

完了は先頭の小文字 x で表します。最初の日付が完了日、次の日付が作成日です。作成日は省略できます。lifetxt の変換では完了日を書き、完了タスクの優先度を保持する場合は pri:A が使えます。

life.txt への変換

通常の行／x
[ ] T／[x] T
(A)・pri:A
priority:A
+Work
project:Work
@office
context:office。Quick 省略記法の @home は project:home になるため、入力形式で意味が変わります。
行頭付近の日付
未完了なら作成日 created:。完了なら完了日 done:、作成日 created: の順です。
due:2026-12-01
due:2026-12-01。期限は due: に明示します。
メタデータ
est:25m や tag:重要 tag:経理 など。プロジェクトとコンテキストも複数指定できます。

変換時に既定の source:todo.txt と id: もプレビューに表示されます。日付や値に構文上の問題がある場合、プレビューはエラーとして返ることがあります。値に空白が必要な項目は正式な life.txt 形式が使えます。
