# Decisions

| Date | Decision | Owner | Alternatives | Reason | Follow-up |
| --- | --- | --- | --- | --- | --- |
| 2026-09-20 | Keep the ordinary Web backup surface read-only and place any run operation only in Remote Safe Mode | Codex (investigation) | Add POST beside `/api/backup/status`; trust reverse-proxy authentication | The ordinary application has no authenticated principal or application-level scopes, while Remote already enforces authentication, protocol, CSRF/Origin, rate limits, and audit | Owner approval; #870 |
| 2026-09-20 | Require a new explicit `backup:run` scope not inherited from owner, admin, or write | Codex (investigation) | Reuse write/admin; include in owner | Starting a backup can consume storage/network and trigger retention, so generic content-edit or administration authority is too broad | Authorization-matrix tests in #870 |
| 2026-09-20 | Dispatch only the fixed generated `lifetxt-backup.service` | Codex (investigation) | Run backup logic in the web worker; expose generic systemd service control | The unit is already the hardened server execution boundary and invokes the canonical scheduled orchestration; fixed dispatch avoids request-controlled commands or units | Narrow privileged runner in #870 |
| 2026-09-20 | Use asynchronous 202 admission with idempotency, an admission lock, and a dedicated per-principal cooldown | Codex (investigation) | Synchronous HTTP run; rely only on the destination lock | Backup duration is unbounded for an HTTP request, retries must not duplicate work, and the existing destination lock starts too late to prevent a queue of accepted systemd requests | Durable lifecycle design and race tests in #870 |
| 2026-09-20 | Keep local and remote outcomes independent and sanitized | Codex (investigation) | Return systemd/journal or rclone output; use one overall success flag | Existing orchestration deliberately treats local creation and off-host upload separately, while raw diagnostics may reveal paths, targets, or credentials | Normalized status contract in #870 and presentation in #871 |
| 2026-09-20 | Leave restore, prune, delete, configuration, and arbitrary upload CLI/operator-only | Codex (investigation) | Create a general backup administration API | Those actions have materially greater destructive or secret-management risk and are not required for the requested run-now decision | File separate High-assurance designs if later required |
