# Definition of Done

An issue is done when:

- all acceptance criteria are met
- required tests are added or an approved exception exists
- formatting, lint, tests, and project checks pass or are reported as not run
- affected documentation is updated
- security impact is reviewed
- compatibility impact is reviewed
- applicable review viewpoints are addressed
- applicable test viewpoints are addressed
- implementation was reviewed by a separate party
- pull request is merged
- follow-up work is captured as separate issues

Do not mark an issue `Done` before the required pull request is merged.
