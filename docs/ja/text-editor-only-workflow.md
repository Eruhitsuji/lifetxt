# テキストエディタだけで使う週次運用ガイド

許可されたテキストエディタだけで、タスクとメモを管理するための運用例です。
外部アプリ、CLI、Python、Git、Web UI、外部SaaS、ネットワーク接続は不要です。
制限のある職場・学習環境やオフライン環境で、lifetxtをソフトウェアではなく
**プレーンテキストのタスク管理フォーマット**として使います。

**これは運用パターンの一例であり、life.txtフォーマットの必須要件ではありません。**
週次ファイルも以下の記法の選択も任意です。通常の単一ファイル運用や
[フォーマット仕様](./life_txt_format_spec.md)を変更・制限しません。
[最初の5分](./getting-started.md)と同様、既存記法の一部だけを使います。

## 1. ファイルを用意する

許可された保存場所に、エディタの「新規作成」「名前を付けて保存」で作成します。
プレーンテキスト・UTF-8で保存し、1週間に取り組むタスクを1ファイルに置きます。
実施時期が未定のものは `someday.txt` に置きます。設定ファイルは不要です。

```text
2026-W40.txt
2026-W41.txt
2026-W42.txt
someday.txt
```

この例の週番号はISO週番号（月曜始まり）で、W40は9月28日〜10月4日、
W41は10月5日〜11日、W42は10月12日〜18日です。
週番号が分かりにくければ、開始日による `2026-10-05.txt` などでも構いません。
ファイル名でアプリが自動的に日付や状態を設定するわけではありません。

## 2. 最小記法

1行に1件を `状態 種類 "タイトル" 属性` の順に書き、区切りには半角スペースを使います。
タイトルや属性値に空白がある場合は半角の `"` で囲みます。
見出しや補足は、行頭に `#` を付けたコメントにします。

| タスクの状態 | この運用での意味 |
| --- | --- |
| `[ ]` | 未着手・未完了 |
| `[/]` | 作業中 |
| `[x]` | 完了 |
| `[-]` | キャンセル |
| `[>]` | 別の週・ファイルへ移動済み（仕様上は延期または移動） |

| 種類・属性 | 用途 |
| --- | --- |
| `T` | Task：タスク |
| `N` | Note：メモ |
| `project:alpha` | プロジェクト名。`project:` の後ろに値を入れる |
| `priority:high` | 優先度が高いタスクにだけ付ける |
| `due:2026-10-09` | 期限。`YYYY-MM-DD` 形式で必要なものに付ける |

メモにはタスク状態と別の既存の状態 `[N]` を使い、`[N] N "メモ"` と書きます。
種類の `N` と状態の `[N]` は別の欄です。属性は省略できます。
期限は週の予定日ではないので、持ち越しだけを理由に書き換えません。

`2026-W41.txt` の開始テンプレート：

```txt
# 2026-W41: 2026-10-05 - 2026-10-11
# 今週
[ ] T "設計レビューを準備する" project:alpha priority:high due:2026-10-09
[/] T "不具合の再現条件を調べる" project:alpha
[N] N "再現条件は入力順序も確認する" project:alpha

# Inbox
[ ] T "手順書の更新箇所を確認する" project:alpha
```

`# Inbox` は未整理のタスクを追記する場所を示すだけのコメントです。
専用機能や特別な構文ではありません。後で取り組みたい項目は `someday.txt` へ：

```txt
# Someday
[ ] T "検証手順の改善案をまとめる" project:alpha
```

## 3. 日次フロー

1. 始業時に今週のファイルを開き、`[/]` を検索して継続中の作業を確認します。
2. 当日が10月7日なら `due:2026-10-07` を検索します。さらに `due:` を検索して日付を読み、期限超過や近い期限も確認します。当日検索だけでは期限超過は見つかりません。
3. `priority:high` を検索し、各行の状態を見て、未完了の中から今日取り組むものを選びます。
4. 着手する行を `[ ]` から `[/]` に変更して保存します。
5. 新規タスクは `# Inbox` の下へ `[ ] T "次にすること"` の形で追記します。
6. 完了したら `[/]`（または `[ ]`）を `[x]` に変更して保存します。
7. 終業前にInboxと `[/]` をレビューします。Inboxの項目を今週欄へ移すか、somedayへ移すか、キャンセルするか判断します。作業途中のものは `[/]` のまま残せます。

自動通知や自動期限判定はありません。エディタで状態・日付を読み、手動で判断します。

## 4. 週次レビューと持ち越し

週末または翌週開始時に、旧週と新週のファイルを開いて確認します。

| 旧週の項目 | 扱い |
| --- | --- |
| `[x]`、`[-]` | 旧週に残す |
| `[ ]`、`[/]` で翌週も行うもの | 新週へコピーし、保存・内容確認後に旧週を `[>]` にする |
| すぐに行わないもの | `someday.txt` へコピーし、保存・確認後に元の行を `[>]` にする |
| 不要になったもの | `[-]` にする |
| メモ | 原則旧週に残し、継続作業に必要なものだけ新週にもコピーする |

新しい行の状態は、改めて着手するなら `[ ]`、実際に継続中なら `[/]` にします。
タイトル・project・priority・期限を確認し、未完了タスクを無条件に持ち越さず、
「本当に次週に行うか」を毎週判断します。somedayも確認し、今週行うものを同じ手順で移します。

例えばW41からW42へ持ち越した後の旧ファイル `2026-W41.txt`：

```txt
# 移動先: 2026-W42.txt
[>] T "不具合の再現条件を調べる" project:alpha due:2026-10-09
[x] T "設計レビューを準備する" project:alpha priority:high due:2026-10-09
[-] T "不要になった調査を行う" project:alpha
```

新ファイル `2026-W42.txt`：

```txt
# 移動元: 2026-W41.txt
[ ] T "不具合の再現条件を調べる" project:alpha due:2026-10-09
```

この例の期限超過はそのまま残し、新週で対応を判断します。`[>]` や移動先コメントは
自動でリンクや移動を行いません。コピー先を先に保存してから元の行を変更し、
中断した場合は両方を見比べ、同じタスクが未完了のまま二重に残らないよう確認します。
旧週は履歴として残し、通常の作業・検索は今週とsomedayを対象にします。

## 5. テキスト検索を簡易UIにする

エディタの検索を**正規表現ではなく文字列そのままの検索**にします。
`[ ]` には半角スペースが1つあります。複数ファイル検索がなければ1ファイルずつ開きます。

| 検索文字列 | 確認できる項目 |
| --- | --- |
| `[/]` | 作業中 |
| `[ ]` | 未着手・未完了 |
| `priority:high` | 優先度が高い行。完了・移動済みも一致するので状態を確認 |
| `project:alpha` | alphaに属する行 |
| `project:` | プロジェクトが付いた行 |
| `due:2026-10-07` | 指定日が期限の行 |
| `due:` | 期限が付いた全行。日付を読んで期限超過・直近を確認 |

検索は一致箇所への移動・強調表示です。構造化フィルターではないため、コメントや
メモの文中も一致し得ます。状態は行頭で確認し、全置換で一括変更しないでください。

## 6. 保存と情報の扱い

編集後とファイル移動の各段階で保存し、所属組織の規程に従った保存場所・
バックアップ方法を使います。特定企業の規程への適合を保証するガイドではありません。
パスワード、APIキー、アクセストークン、秘密鍵、その他の認証情報や、
規程上保存が認められていない情報をlife.txtに保存しないでください。
