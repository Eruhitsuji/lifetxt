# Editor Release Distribution — Design

- Owner decision (2026-10-24): approved 13+1 strict target, independent VS Code 3-part SemVer, single preflight candidate with two Windows editor archives, aggregated final main PR. Related tasks #1390 → #1391 → #1392.
- Build: `release_preflight_editor.py` runs a locked npm production install and pinned vsce build in a disposable copy of the exact source SHA. The VSIX must contain the unbundled `vscode-languageclient` runtime dependency. Python LSP is optional and is not bundled or installed.
- Neovim: archive only the existing Lua configuration, bilingual Windows apply/remove instructions, and stamped provenance. `init.lua` is never modified by the installer or package.
- The sealed `editor-windows` component uses standard `proof.component`, two mandatory roles and four smoke checks. It is passed through the same producer job API, attempt, source, aggregate, artifact expiry and release plan validations as the thirteen original targets.
- Public assets are included through existing `release_canonical.public_inventory` and the one canonical SHA256SUMS. There is **no second checksum writer** or publisher. `release_channels.verify_github` reads public bytes first, then validates archive interior and source/release/editor versions.
- Version mapping: release file names use lifetxt X.Y.Z[.N]; VSIX manifest and extension `package.json` keep their own three-number extension version. Both archives carry JSON binding to source SHA, immutable candidate digest and both versions. An old 13-target bundle cannot authorize a 14-target candidate.
- Safety: no arbitrary path extraction, no archive symlinks, duplicate or traversal paths, no editor writes, no extra external channel, no additional release token. Failed bytes/manifest/scan block preflight/verify and Latest; no in-place tag replacement.
- Recovery is the existing #1308 rule: repeat a matching immutable preflight with new environment approval after transient failure; source defects require a new human-selected correction version and fresh preflight. The historical published version is never overwritten.
- Validation boundary: offline synthetic fixtures demonstrate contract transitions; actual packaged VSIX and full GitHub Actions preflight must be exercised before any future Release is approved. Human Windows GUI evidence and remaining unexecuted cases are recorded in #1373.
