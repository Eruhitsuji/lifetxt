## Reproduce and interpret

Run with a supported Python runtime:

```console
python scripts/benchmark_core.py \
  --output docs/en/core-performance-baseline.json \
  --markdown docs/en/core-performance-baseline.md
```

Use `--sizes 1000 10000` for a quick smoke run. The JSON includes the
benchmark version and commit, deterministic fixture hashes, record/byte sizes,
operation timings, and platform metadata. Compare repeated runs on comparable
machines; do not turn one machine's timings into universal hard limits.

The Web/server and TUI paths are omitted because ports, optional dependencies,
terminal rendering, and process scheduling make their startup timings
environment-dependent. Measure those paths with a deployment-specific harness.

## Current evidence

On the recorded Windows run, the 200,000-record single-file fixture was about
16.8 MB and took about 0.57 seconds to parse and 0.68 seconds to validate.
The equivalent two-source layout took about 0.79 seconds to parse and 0.68
seconds to validate. This indicates roughly linear parse/validation growth and
a measurable but not yet operationally dominant multi-source overhead for this
fixture. The query, agenda, and deterministic today calculations remained below
one millisecond because their work is performed on already-parsed records.

This evidence supports advisory storage-health measurements before automatic
archive rotation. It does not justify universal thresholds or an index yet:
the benchmark should be repeated with production-shaped custom details and
larger files before choosing either. Archive rotation remains a later safety
and operations decision, separate from this read-only measurement.
