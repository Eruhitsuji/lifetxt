# Web secure transport

One Security/High assurance change, M justified: proxy identity, Origin, warning and documentation form one deployable boundary. Extend the upload and Remote browser capabilities; reuse remote.trusted_proxies. No mandatory dependency, config schema/default/provenance/version change, data change or migration.

serve/web explicitly pass proxy_headers=False so the socket peer cannot be rewritten by Uvicorn or FORWARDED_ALLOW_IPS. expected_origin accepts only direct Host or single validated X-Forwarded-Proto/Host values from a configured immediate peer. The standard Forwarded header is unused. Upload compares scheme/hostname/effective port and preserves marker/Fetch Metadata/no-CORS checks before reading bytes. Remote rejects invalid effective origins even with an explicit allowed_origins entry. Existing Remote HTTPS and cookie rules remain.

Normative non-loopback protection is TLS termination with a protected backend or an authenticated encrypted tunnel over every untrusted hop. Non-loopback writable binds warn; no claim to infer physical encryption from an HTTP scheme or private address. Existing public token refusal remains. HTTP already received cannot be protected by a refusal. Read-only sensitive reads need equal protection. Sensitive possession-granting URLs require no logging/shared caching and short scope/expiry; future resource endpoints remain out of scope.

The nginx example sets fixed external Host and forwarded host (include external non-default port), overwrites scheme/client address, strips unverified principal/Forwarded, and adds no-referrer. Its HTTP listener rejects requests rather than redirecting mutation payloads. Operators must configure default-server rejection for unknown hosts and independent access control. Config trust list applies even without Remote enabled, and additionally grants existing Remote proxy assertion authority when enabled.

Review/test viewpoints: peer spoofing, duplicated/malformed origin, HTTPS proxy success, origin/port mismatch before storage, auth/read-only/revision regression, local HTTP, secret-free warning, no-Web import boundary, log/cache guidance. Custom ASGI deployments must preserve the peer. Upgrade requires explicit narrow proxy trust and service restart; downgrade requires reevaluating the older implicit trust. Revert PR for rollback; no journal/data migration.
